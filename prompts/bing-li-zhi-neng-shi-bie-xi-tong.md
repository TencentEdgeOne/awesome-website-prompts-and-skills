2.1 完整版结构化提取
--------------------------------------------------------------------------------

# 病历结构化提取任务

## 输入信息

### OCR 原始文本
{ocr_text}

### 参考知识库内容（可选）
{knowledge_context}

## 输出要求

请严格按照以下 JSON Schema 输出：

{
  "patient_name": "患者姓名（string，无则为null）"，
  "gender": "性别（男/女/未知）"，
  "age": "年龄（number，无则为null）"，
  "date": "就诊日期（YYYY-MM-DD 格式）"，
  "diagnosis": "主要诊断"，
  "symptoms": ["症状列表（array）"]，
  "medications": [
    {
      "name": "药品名称"，
      "dosage": "单次剂量"，
      "frequency": "用药频率"
    }
  ]，
  "advice": "医嘱建议"，
  "follow_up": "复诊建议"，
  "confidence": "置信度（0-1）"，
  "extraction_notes": "提取说明或注意事项"
}

## 处理规则

1. 患者姓名：优先从"姓名"、"患者"、"姓名："等关键词后提取
2. 日期格式：统一转换为 YYYY-MM-DD，无法确定时使用 XXXX-XX-XX
3. 药品拆分：如果药品名称包含剂量信息，需要拆分
   例如："头孢克肟 0.1g x 3次/日" → name="头孢克肟"， dosage="0.1g"， frequency="每日3次"
4. 置信度评估：
   - 0.9-1.0：信息明确，可靠性高
   - 0.7-0.9：信息基本可靠，有少量模糊
   - 0.5-0.7：存在较多不确定内容
   - <0.5：信息可靠性低，需人工确认
5. 症状提取：从"症状"、"主诉"、"现病史"等部分提取
6. 医嘱处理：包括饮食建议、运动建议、复诊时间等

## 注意事项

- 如果某些字段无法确定，请使用 null 或空数组
- 药品名称尽量使用标准名称，避免使用商品名
- 如果 OCR 文本中包含多个就诊记录，只提取最新的一个
- 遇到模糊或不确定的内容，根据上下文合理推断，并在 confidence 中体现

直接输出 JSON 对象，不要包含任何其他文字说明。
